# 글쓰기 AI로 정리하기

- 글 작성·수정 모달의 서술형 입력 아래에 기존 네이비 색·카드·칩 스타일을 사용한 제안 영역을 추가한다. ZIP에 별도 디자인이 없는 기능이므로 기존 폼의 스타일을 재사용한다.
- ‘AI로 정리하기’를 눌러야 `POST /api/ai/analyze`를 호출한다. 자동 요청·자동 재시도·글 저장은 하지 않는다.
- 잘된 점·아쉬운 점·배운 점 중 하나를 입력해야 한다. 선택 전 분류는 null로 보내며, 제목과 네 서술형·결과·도전 유형·단계만 전송한다. 작성자 정보·기존 태그는 요청 필드에 포함하지 않는다.
- summary / suggestedTags / keyLessons / nextTip을 한 줄 요약·추천 태그·핵심 배움·다음 팁으로 표시한다. 한글 태그는 글쓰기와 같은 프론트 enum 매핑을 사용한다.
- AI가 본문을 덮어쓰지 않는다. 사용자가 추천 태그를 선택하고 ‘선택한 태그 적용하기’를 눌러야 기존 태그에 중복 없이 추가한다. 서버에 없는 태그 코드는 제외한다. 실제 글 저장은 기존 등록·수정 저장 버튼으로만 수행한다.
- 분석 중에는 폼 수정·글 저장·중복 분석을 막고, ‘분석 취소’를 제공한다. 취소·이탈 시 요청을 중단하며 이전 요청의 늦은 결과가 다시 반영되지 않게 요청 번호를 확인한다.
- 결과에 영향을 주는 본문·제목·분류가 바뀌면 이전 제안 적용을 비활성화하고 재분석을 안내한다. 수동 태그 변경만으로는 재분석을 요구하지 않는다.
- 입력 부족·네트워크 오류·429 사용량 제한·503 AI 서비스 오류를 처리한다. 오류가 나도 폼을 유지하고 직접 작성을 계속할 수 있다. 503은 서비스 설정 파일명 대신 사용자용 안내를 표시한다.
- 개발 전용 마이페이지 수정 미리보기에도 모의 AI API를 주입해 실제 AI 호출이 발생하지 않게 한다.

## 디자인 확인

- `http://localhost:5173/?preview=write-ai`
- `http://localhost:5173/?preview=write-ai&state=empty`
- `http://localhost:5173/?preview=write-ai&state=error`

실제 AI·계정·게시글 저장소를 사용하지 않는다. 미리보기 코드는 배포 빌드에서 제외한다.

## 검증

```powershell
npm run build
npm run lint
node --experimental-strip-types --test tests/*.test.mjs
node --experimental-strip-types scripts/verify-draft-ai-api.mjs --check-missing-key
```

마지막 명령은 AI 키가 없는 localhost:8080 개발 서버에서만 실행한다. 빈 요청 400, 키 미설정 503, 분석 전후 내 글 ID가 동일한 것을 확인한다. 글을 생성하거나 수정하지 않는다.

현재 로컬 환경에서 실제 AI 생성 성공은 확인하지 못했다. 키 설정 후 네 결과 필드·태그 적용·실제 등록/수정까지 추가 통합 검증이 필요하다. 제안 성공·태그 병합·입력 변경 시 차단·취소·오류 후 폼 복구는 모의 API 테스트와 브라우저 미리보기로 확인했다.
