# 게시판 API 연동

## 로컬 실행

백엔드는 JDK 17이 필요하다. 저장소의 backend 폴더에서 `./gradlew.bat bootRun`으로 실행한다. 기본 DB는 H2 메모리 DB여서 백엔드를 재시작하면 등록한 글도 초기화된다.

프론트는 frontend 폴더에서 `npm install`, `npm run dev`로 실행한다. 기본 주소는 http://localhost:5173 이다. `/api` 요청은 Vite 프록시가 http://localhost:8080 으로 전달한다. 포트 충돌 시 다른 개발 서버를 종료하고 재실행한다.

별도 서버를 사용할 때만 `.env.example`을 참고해 `.env.local`에 VITE_API_BASE_URL을 지정한다. 이 값은 브라우저에 공개되므로 API 키나 JWT를 넣지 않는다. Vite 프록시는 개발용이며 배포 환경에서는 별도 API 주소 또는 리버스 프록시가 필요하다.

## 구현 범위

- GET /api/me의 닉네임 표시
- GET /api/posts의 서버 필터·검색·정렬·페이지네이션
- GET /api/posts/{id}와 도움이 돼요 상태 조회
- POST /api/posts로 등록 후 해당 결과 탭의 첫 페이지 갱신
- 도움이 돼요 추가·취소와 서버가 반환한 수·성장 단계 반영
- 요청 중 상태, 재시도, 오류 메시지, 작성 실패 시 입력 보존

목록 응답에는 본문 미리보기가 없어서 목록에서는 해당 영역을 표시하지 않는다. 결과 탭에 결과별 전체 건수를 반환하는 API도 없으므로 탭별 건수를 임의로 계산하지 않는다. 목록 상단 건수는 필터된 전체 totalElements를 사용한다.

## 인증

개발 모드에서 토큰 없이 요청하면 서버가 1번 사용자를 선택하지만, 프론트는 이를 로그인으로 인정하지 않는다. 프론트는 개발용 X-User-Id를 자동으로 보내지 않는다. localStorage의 blooming.token에 저장된 토큰이 있으면 Authorization Bearer 헤더를 붙이고 /api/me로 실제 사용자를 확인한다. 401이면 토큰을 지우고 로그인 팝업을 표시한다. 로그인 화면 실행 방법은 auth-local-run.md를 참고한다.

## 확인할 흐름

1. 내 정보의 닉네임과 서버의 시드 게시글 확인
2. 탭·도전 유형·검색·정렬 변경 후 결과 및 페이지 수 확인
3. 글 열기 → 상세 본문 확인 → 반응 추가·취소 → 목록 반응 수 확인
4. 내 글에는 반응 버튼이 비활성화되는지 확인
5. 글 작성 → 서버 등록 → 목록에서 열기 → 프론트 새로고침 후에도 글이 남는지 확인
6. 백엔드 종료 후 오류·재시도, 등록 실패 시 입력 보존 확인

`npm run build`, `npm run lint`, `node --experimental-strip-types --test tests/*.test.mjs`로 정적 검사와 계약 테스트를 실행한다.

## 남은 범위

마이페이지·수정·삭제·신고·요인 분석·AI는 별도 기능 브랜치에서 구현한다. 저장(북마크)은 대응 API가 없어 여전히 화면 내 임시 상태다. 배운 점 필수는 현재 프론트 정책이고 서버 DTO는 아직 선택이므로 최종 합의가 필요하다.
