# AI 로드맵

- 최신 Figma Make ZIP의 마스코트 헤더, 3열 행동 카드, 체크 항목과 하단 행동 관리 영역을 사용한다. 모바일 CSS에서는 1열로 배치한다.
- AI 로드맵 버튼·프로필 메뉴·마이페이지 바로가기·`/#roadmap`으로 이동한다. 로그인 확인 후에만 개인 API를 호출한다. 사용자별 page key로 이전 계정 데이터를 폐기한다.
- ZIP의 고정 진로명·진로 단서는 서버 응답에 없어서 표시하지 않는다. 서버 분류 `keep / improve / tryNew`를 ‘유지할 행동 / 개선할 행동 / 새로 시도할 행동’으로 표시한다.
- `GET /api/roadmaps/availability`로 내 글 수·추가 필요 건수·생성 가능 여부를 표시한다. 내 글 3건 미만이면 새 생성 버튼을 비활성화한다.
- 유형 선택 시 `GET /api/roadmaps/latest?challengeType=...`만 호출한다. 404는 저장된 결과 없음으로 처리한다. 새 생성은 사용자가 명시적으로 버튼을 눌렀을 때만 `POST /api/roadmaps`로 요청한다.
- 새 로드맵은 서버가 자동 저장한다. 생성 실패 시 기존 결과와 선택 문장을 유지한다. 생성·담기 중 중복 요청과 유형 변경을 막는다.
- 선택한 문장을 1~100자로 고쳐 `POST /api/checklist/bulk`에 `source: ROADMAP`으로 담는다. 완료 체크가 아닌 ‘담을 항목 선택’이며, 실제 완료·추가·수정·삭제는 체크리스트 관리에서 한다.
- 문장 수정은 담을 체크리스트 문장에만 적용한다. 저장된 원본 로드맵 수정 API는 없다.
- 성공 응답 후에만 담기 완료를 표시한다. 같은 화면의 완료 항목은 재전송하지 않는다. 서버에는 중복 방지 키가 없어 재조회·새로고침 후 같은 항목을 다시 담으면 별도 항목으로 저장될 수 있다.
- 기록이 부족해도 과거에 저장한 결과는 조회할 수 있다. 조회 실패·재시도, 생성 오류, 기록 부족, 빈 결과, 비로그인 안내를 제공한다.
- 이탈 시 조회·생성 요청을 취소한다. 프론트 요청 취소가 서버의 AI 호출·저장 취소를 보장하지 않으므로, 다시 진입하면 최근 결과를 먼저 조회한다. POST를 자동 재시도하지 않는다.

## 미리보기

개발 서버에서 실제 AI·API·토큰·저장소 없이 UI를 확인한다. 배포 빌드에서는 제외된다.

- `http://localhost:5173/?preview=roadmap`
- `&state=empty`: 저장된 결과 없음
- `&state=shortage`: 기록 부족
- `&state=error`: 생성 실패 및 기존 결과 유지
- `&state=save-error`: 체크리스트 저장 실패
- `&state=load-error`: 최근 결과 조회 실패

## 검증과 제한

```powershell
npm run build
npm run lint
node --experimental-strip-types --test tests/*.test.mjs
node --experimental-strip-types scripts/verify-roadmap-api.mjs
```

실제 로컬 백엔드에서 생성 가능 여부·최근 결과 조회(없으면 404)·3건 미만 생성 제한·ROADMAP 체크리스트 저장 및 정리를 검증한다.

이번 로컬 환경은 AI 키가 설정되지 않아 실제 생성 요청이 503을 반환했다. `--check-missing-key` 옵션으로 해당 응답까지 확인했다. 실제 AI 생성 성공과 결과의 자동 저장·재조회는 백엔드의 AI 키 설정 후 추가 검증이 필요하다. 생성 성공 흐름·문장 선택/수정/담기·실패 시 결과 유지는 미리보기와 모의 API 테스트로 확인했다.
